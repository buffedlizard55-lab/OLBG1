Analysis and irregularity proofs

The timezone proof, the band arithmetic, the source ledger and the coverage gaps.

OLBG hub routing

Routes are olbg.com/betting-tips/<Sport>/<id>. The sport token is case sensitive in the slug while the numeric id does the routing; a hub opened without its id returns a soft 404. The hub listing is paginated behind a "Load More Tips" control, so a hub can list more rows than it renders on first paint (ED71-F-16).

The display clock is unlabelled US Eastern

OLBG hub pages render start times in America/New_York EDT (UTC-4) with NO timezone label printed anywhere on the page.

Conversion used: utc = rendered_time + 4h

  • Greyhound race whose event name embeds the UK local clock '5:12 Towcester' renders as 'Today 12:12'. 17:12 BST = 16:12 UTC = 12:12 EDT.
  • NHL 'MTL Canadiens @ CHI Blackhawks' renders 'Today 20:07'; nhl.com publishes 8 p.m. ET.
  • Rugby Union 'Aurillac v Nevers' renders 'Today 13:30' = 17:30 UTC = 19:30 CEST, a standard Pro D2 kick-off.
Consequence. A reader who assumes UTC or UK time reads every kickoff four hours early. All times published here are converted to UTC, and the OLBG-rendered value is kept alongside so the conversion can be audited row by row.

Start times are padded

OLBG start times carry an unlabelled +5 to +7 minute padding (ED71-F-02): NHL Montreal at Chicago renders 20:07 against an official startTimeUTC of 00:00:00Z, which is 20:00 ET. OLBG renderings are therefore never published as the kickoff; the official time is used and the rendering is shown next to it.

A timezone defect that changes the calendar day

Four OLBG darts rows render a 24 October date for first-round matches that sit in the 23 October evening session once the +4h offset is applied (ED71-F-05). Read naively this looks like a reschedule. It is the unlabelled clock pushing a late European evening past midnight in the display zone. Dates on this desk come from the promoter's session calendar.

Why the high-confidence band admits so few picks

Fair decimal price is 1/p with no margin. A price of -250 is decimal 1.400, which corresponds to p = 0.71429. Therefore the brief's conjunction - probability at least 70% AND price no shorter than -250 - can only be satisfied inside the 1.43-point window p in [0.700, 0.71429]. Every selection above 0.71429 is a genuine 70%+ preference but is priced shorter than -250, so it is disclosed in the out-of-band ledger and is not promoted to High. That is arithmetic, not caution.

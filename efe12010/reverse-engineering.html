OLBG reverse-engineering

The structure of OLBG's tip hubs, the timezone trap, and the full discovery harvest.

15 hubs106 cards captured

How OLBG's public tip hubs are put together, what they expose, and the four behaviours that will break a naive harvest. This page is the discovery layer in full; nothing here is treated as a confirmed sporting fact.

URL architecture

Every sport hub follows the same shape: olbg.com/betting-tips/<Sport>/<id>, where the id is a stable small integer. The sport name in the path is cosmetic — the integer is what routes. Individual cards hang off /betting-tips/<Sport>/<id>/<event-id> with a six-digit event id, and the same event id reappears across markets on that event.

Each card exposes four machine-readable quantities: the number of tips, the number of tipsters on the leading selection, that selection's share as a percentage, and the market the consensus applies to. There is no odds field and no timezone field.

The four behaviours that break a naive harvest

  1. Clocks are rendered in the viewer's zone with no label. A scraper that records "Today 20:00" and stamps it UTC will be four hours wrong for every row in this session's region. The fix is an independent cross-check against an official feed, which is what the timezone table below does.
  2. Empty hubs return a success page. Golf answers with the literal string "No tips found." under a normal 200 response, so status-code-only monitoring records a healthy scrape of a sport that produced nothing.
  3. Outright-only sports look identical to failures. Rugby league returned three ante-post outrights and zero match cards. Without parsing the card type, that is indistinguishable from a broken selector.
  4. Each-way markets can render a null consensus. The T20 Blast 2027 outright, event 188350, shows 0/0 tipsters and an empty percentage while still reporting a non-zero tip count — an internal inconsistency that will produce a divide-by-zero in any consensus calculation.
